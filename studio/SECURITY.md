# Security policy

Do not post credentials, private project exports, contact messages or exploit details in public issues. Report privately to the repository owner through a private GitHub security advisory when available; otherwise request a private contact channel from the maintainer. No email address is invented here.

Use the latest supported 0.1 revision and Node 24 security patches. Configure HTTPS and separate editor/public origins before exposing an instance. Close registration if not intended for public signups. Do not run multiple workers. Back up the database and shared data volume together. See docs/SECURITY.md for trust boundaries, limitations and hardening.
