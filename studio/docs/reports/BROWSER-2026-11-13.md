# Browser validation, 13 November 2026

The original compact editor rendered a 615 px workspace at a 390 px viewport. It now uses one full-width panel at a time below or at 650 px. Canvas, Structure and Style retain editor state while switching. Fit measures the actual canvas area. The touch regression test inserts a heading, changes its font size, and checks the saved result after reloading.

WebKit initially upgraded localhost assets to HTTPS and failed to start the editor. The server now omits the upgrade directive for explicitly configured loopback HTTP origins. Production HTTPS configuration retains the directive. See the [Helmet CSP documentation](https://helmet.js.org/#content-security-policy). The in-app browser opened the studio but retained its PWA update banner after confirmation. The update handler now installs its listener before sending the activation request, and the worker keeps the message event alive during activation. A complete two-version activation test remains outstanding.

- TypeScript check and production web build passed. The build still reports the ancestor Expo tsconfig warning and bundle warnings.
- 39 Vitest tests and 10 Chrome Playwright tests passed. These cover local editing, export, publishing and rollback, offline editing, Ideas, and simulated passkeys.
- WebKit 27.2 at 390 px with iPhone 13 emulation passed landing entry, template creation, panel switching, styling, saving and reload. The canvas view was inspected visually.
- Firefox could launch but the locally cached browser revision rejected the installed Playwright client's browser-context protocol. Firefox compatibility remains unverified.
- Physical phones, installed PWA behavior and native Expo builds remain unverified.

The mobile findings were resolved in the web editor. A React Native editor would require native navigation and storage adapters plus an isolated HTML preview surface. The Expo starter remains separate from the portfolio editor.
